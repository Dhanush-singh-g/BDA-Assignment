# Run 50,000 foods on your laptop

Run these commands in **Ubuntu Terminal**, not Windows PowerShell. This guide
uses your existing project installation and full MongoDB import `fdc_home202410`.
For installation help, see [the technical reference](docs/TECHNICAL-REFERENCE.md).

**Your 50,000-food run already passed.** It included **1,126,928 linked nutrient
records** and 477 nutrient definitions. To show those results, go straight to
**Step 7**. Steps 1–6 explain how that run was made; do not repeat them just to
open the dashboard.

This is a development subset on one laptop with three Docker containers. It is
not a full-dataset run or evidence of three separate physical computers.

## 1. Open the project and update the code

```bash
cd ~/BDA-Assignment
git pull --ff-only origin main
```

- `cd` moves Terminal into the project folder.
- `git pull` gets the latest code/docs from GitHub without creating a merge.

## 2. Stop Hadoop and start MongoDB

```bash
docker compose -f infra/compose.yaml stop
bash scripts/start_mongo.sh
```

- `docker compose ... stop` stops the Hadoop master/workers to release RAM. It
  keeps their saved data.
- `start_mongo.sh` starts the project's local MongoDB container and checks that
  it responds. It keeps the existing full import.

Wait for `MongoDB responds to ping` before proceeding.

## 3. Copy 50,000 foods into a separate development database

```bash
.venv/bin/python -m fdc.dev_subset \
  --source fdc_home202410 \
  --destination fdc_dev50k_01 \
  --foods 50000
```

- `.venv/bin/python` uses the project's installed Python packages.
- `fdc.dev_subset` copies a linked development subset, not the whole database.
- `--source` identifies the existing complete import.
- `--destination` creates a separate database, preserving the source.
- `--foods 50000` selects the first 50,000 foods by source row order, **plus all
  their nutrient records**, and copies nutrient definitions.

This is not random or representative sampling. Our run copied 50,000 foods,
1,126,928 nutrient records and 477 definitions. Wait for `complete: true`.

## 4. Run MongoDB analytics and index comparisons

```bash
.venv/bin/python -m fdc mongo-analytics \
  --database fdc_dev50k_01 \
  --output results/mongo/dev50k_01 \
  --repeats 5
```

- Reads the development database and builds food documents with linked nutrients.
- Calculates food-type counts, nutrient summaries and an overview.
- Runs the same food-ID query with and without an index, five times per method.
- Saves the answers and execution plans under `results/mongo/dev50k_01/`.

Expected completion: `food_count: 50000` and `profile_runs: 10`.

## 5. Export the same records for Hadoop

```bash
.venv/bin/python -m fdc.export_dev \
  --database fdc_dev50k_01 \
  --output data/dev50k_export_01
```

This writes a development CSV ZIP and prepared TSV files for the **same subset**.
It records source/subset fingerprints and counts, allowing other tools' answers
to be checked against MongoDB. Wait for it to finish before stopping MongoDB.

## 6. Switch to Hadoop and run MapReduce, Pig and Hive

```bash
docker stop fdc-mongo-dev
docker compose -f infra/compose.yaml up -d --no-build
```

- The first command stops MongoDB to free memory; it does not delete its data.
- The second starts the master and two workers in the background using the
  installed tools/images, without rebuilding images.

Wait about a minute for services to start. Then run:

```bash
.venv/bin/python tests/real_subset_cluster.py \
  --subset data/dev50k_export_01 \
  --mongo-results results/mongo/dev50k_01
```

This checks the workers and a sample YARN job, demonstrates HDFS file operations,
runs MapReduce, cleans records with Pig, and compares Hive Text/RCFile queries.
It checks counts, sums and means against independent prepared-data totals and
saved MongoDB results. Hive uses a warmup and one measured run per query/format
pair here; these are development measurements, not final repeated benchmarks.

Let it finish even when it is quiet. It prints an evidence folder and should end
with `Distributed development checks passed`. Your successful folder was:

```text
data/realdev_1792244956898668695/
```

Its `SUCCESS.json` confirms completion; `cluster.log` holds detailed job output.
If a different run fails, read the error and its log rather than launching another
copy immediately.

## 7. Open the dashboard for your already completed run

```bash
cd ~/BDA-Assignment
docker compose -f infra/compose.yaml stop
.venv/bin/python -m fdc.dashboard
```

- Stops Hadoop to release RAM. MongoDB was already stopped in Step 6.
- Starts Flask, which reads **saved files**, so neither service needs to run.

Open the address Flask prints in your Windows browser. In **Evidence run**, select:

```text
data/realdev_1792244956898668695
```

Click **Load run**. Show nutrient summaries, MongoDB index comparisons, Hive
query timings, storage measurements and the development-subset label. If you
perform a new successful test later, select its newly printed evidence folder.

To stop the website, press **Ctrl+C** in its terminal. Your results stay saved.

## Important: if you want another processing run

The database/output names above already exist on your laptop. The programs
refuse to overwrite them. Keep the existing run; do not delete it to bypass this.
For a deliberate new run, consistently change all `_01` database/export/result
names to new names such as `_02`. Each run adds data and takes time.

Do not run multiple copies at once. Do not repeat the full import. Back up
`data/dev50k_export_01/`, `results/mongo/dev50k_01/` and your successful
`data/realdev_.../` folder separately—generated results are not stored in GitHub.
